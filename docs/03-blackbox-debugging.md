# 03 · 黑盒取证方法论：没有服务器权限怎么定位线上问题

> 事故 ④⑤⑥ 的定位过程里，我**没有生产服务器 SSH 权限、没有容器日志权限**；上游网关和工单系统都是别的团队的（只能调 API，不能改部署）。这篇是当时被迫锤炼出来的方法论——后来证明它比"登上去看日志"更可靠，因为它强迫你把问题变成实验。

## 心法：从"查日志"到"做实验"

有日志权限时的调试是**考古**：翻现场，找线索。没有日志权限时只能**复现实验**：构造输入，观察输出，控制变量。

考古的问题是：日志里有的只是"发生了什么"，不是"为什么"。实验的优势是：**你可以只变一个变量**。六次事故里最关键的几条铁证（输入差三倍耗时不变、超时点整齐、带禁令仍去核验文件）没有一条能从日志里直接读出来——它们都是对照实验的产物。

## 三件仪器

### 仪器一：健康检查接口（地面实况）

服务自带 `/health`，返回三档模型的启动探针结果和熔断器快照。任何排查第一步先打它：

- 三档全绿 → 排除"整个网关挂了"这种大面问题，把注意力收窄到"特定路径/特定规模"；
- 某档红 → 直接看熔断状态，省掉一轮猜测。

**教训：健康检查要反映"启动时探针 + 当前熔断快照"，但不要做实时探测**——否则健康检查自己会打挂网关。

### 仪器二：合成 prompt 直打（变量隔离）

最有威力的一件。构造与真实场景**同形状**、但大小/模型/指令**可控**的合成请求，直接打 API，一次只变一个变量：

- 同一尺寸、同一模型、不同时间 → 测稳定性和排队；
- 同一模型、不同尺寸（37KB vs 12KB）→ 测"是模型在算还是在排队"（**输入差三倍、耗时不变 = 排队**）；
- 同一尺寸、不同模型/通道 → 定位是通道级还是模型级；
- 加不加 prompt 级禁令 → 测指令对 agentic 行为的实际约束力。

三条实操纪律：

1. **单消息请求**绕过上下文压缩（消息数少于保留窗口），保证测的是裸网关，不是你的中间层；
2. 记录**墙钟时间**而不是只看成功/失败——秒级失败和超时失败是**两种完全不同的病**（秒级失败 = 请求没被受理，如 E2BIG；超时 = 受理了但没跑完）；
3. 每组至少两次，确认可复现再下结论。

### 仪器三：SSE 思考流（飞行记录仪）

给长任务加实时进度流：每个阶段的开始/结束/耗时、每个切片的成功/失败/错误原文，通过 SSE 推给前端。它是用户体验功能，同时也是**事故现场的逐秒回放**——事故 ④ 的"60.0–60.1s 整齐超时"、事故 ⑤ 的"90.1s ×6 批次全灭"都是直接从思考流里读出来的。

实现要点（缺一个就当不成仪器）：

- **先开流再执行** + 5s 心跳（否则仪器本身先被网关掐死，见事故 ②）；
- 事件带**结构化字段**（阶段、序号、耗时、错误码），不是纯文本，方便事后解析对齐；
- 失败也要把**失败原因**推出来，并以 200 + 结构化文案收尾——仪器的最后一帧必须存在。

## 两条判读法

### 平坦性分析

延迟曲线的**形状**比绝对值更有信息量：

| 形状 | 含义 |
|---|---|
| 耗时随输入线性/亚线性增长 | 模型在计算（正常） |
| 输入差 3 倍、耗时不变（平坦） | **排队**——时间花在队列里，与你的请求无关 |
| 耗时与输入无关、且远超正常值、多模型同样表现 | **通道级/基础设施问题** |
| 精确死在某个整数值（60.0s、90.1s） | **你自己的超时预算**，不是外部故障 |

### 整齐性分析

一堆失败的超时点如果**散乱** → 外部不稳定（抖动、重试、排队位置不同）；**整齐划一** → 内部确定性机制（你的超时、你的预算、你的限流）在杀它们。事故 ④ 里"60.0–60.1s"的整齐性直接把侦查方向从"网关不稳定"掰到"我的切片超时不够/切片太大"。

## 一张流程图

```
现象
 ├─ /health 三档全绿？ ──否──→ 看熔断快照，走模型级故障路径（四层防御管的事）
 │        │是
 ├─ 秒级失败还是超时失败？
 │        ├─ 秒级失败 ──→ 请求没被受理：查协议层/进程创建层（argv 长度、参数顺序、鉴权）
 │        └─ 超时失败 ──→ 任务被受理但没跑完：
 │                 ├─ 超时点整齐？ ──是──→ 自己的预算不够：缩小任务单元（更小切片）
 │                 │        │否（散乱）
 │                 ├─ 合成 prompt 压测：输入↑耗时平？ ──是──→ 上游排队：对冲/换通道/预算兜底
 │                 └─ 平台日志正常但目标行为异常 ──→ agentic 探索：CLI 级禁工具
```

## 检查清单（可迁移）

下次遇到"线上慢/挂但登不上去"时，按序执行：

1. `/health`（或等价探针）确认地面实况；
2. 区分**秒败**还是**超时**——这决定查协议层还是查执行层；
3. 用同形状合成请求做**单变量**对照（尺寸 × 模型 × 指令）；
4. 看**平坦性**和**整齐性**，不是只看平均值；
5. 每个结论必须"修复后现象消失"才算闭环——**能解释的证据不算证据，能预测的证据才算**；
6. 修复时顺手把取证仪器固化（思考流、结构化 perf 字段）——下一个事故会感谢它。
